## Why it matters

Running a model on your own hardware keeps prompts and data off third-party servers and works offline. It also makes you the operator of everything a provider used to handle: the model files, the server that loads them, the network ports it listens on, the tools it can call, and its updates.

MITRE ATLAS records what goes wrong. In 2025, researchers at ReversingLabs found models on Hugging Face, the largest public model hub, that opened reverse shells, giving an attacker remote control of the machine, as soon as they were loaded. The files were apparently corrupted on purpose: the payload ran before loading failed, while the hub's scanner needed to deserialize the whole file and missed it (AML.CS0031). The ShadowRay campaign hijacked clusters running Ray, an AI workload framework whose job API runs code by design and offers no authentication; researchers at Oligo found it had been exploited for at least seven months (AML.CS0023). In January 2026 a security researcher found hundreds of control interfaces for a self-hosted AI assistant exposed on the public internet, some without authentication. Their configuration files held credentials for connected services, and the assistant's shell skill led to root access in its container (AML.CS0048).

## The core idea

A local deployment is a stack, and each layer has its own trust question:

| Layer | What it includes | Question to ask | Typical failure |
| --- | --- | --- | --- |
| Model files | Weights, tokenizer, chat template, configuration | Can loading or using them run someone else's logic? | Pickle code execution; a poisoned template |
| Inference server | The program that loads the model and serves an API | Who can reach it, and is each caller identified? | All interfaces, no key |
| Tools | Code execution, shell, browsing, file writes | What can a steered model do? | A shell tool running as root |
| Host and operations | Operating system, containers, updates, logs, licenses | What is patched, recorded, and permitted? | A stale runtime; prompts logged forever |

Three rules summarize the lesson. Treat model files as untrusted input that might be code. Treat the inference API as a privileged service that spends compute and holds conversations. Treat every tool call as untrusted code, because [prompt injection](lesson:AI-01) can steer a local model exactly as it steers a hosted one.

## How it works

> [!ETHICS] Only test systems you own or have written permission to test.

### Model files: data or code?

Python's pickle format stores a sequence of instructions for rebuilding objects, and those instructions can name an importable function and call it with arguments. Whoever writes a pickle therefore decides what runs when it is loaded. This is the classic case of [[insecure-deserialization]] (CWE-502). PyTorch's standard checkpoint files, often named `.pt`, `.pth`, or `.bin`, are pickle-based, as are `.pkl` files. ATLAS warns that pickle files "can contain exploits that allow for arbitrary code execution" (AML.M0016) and, after the Hugging Face case, that "pickle files are fundamentally unsafe as they allow for arbitrary code execution." Scanning helps, but ATLAS adds that scanners must handle files that cannot be fully deserialized, since attackers corrupt files on purpose.

[[safetensors|Safetensors]] avoids the problem by storing only tensors, the named arrays of numbers that make up a model, plus metadata. Its documentation describes it as a format for storing tensors "safely (as opposed to pickle)" that is "still fast." GGUF, a common format for running language models locally, also stores weights as data, but it bundles configuration and chat-template logic in the same file. ATLAS records researchers who poisoned GGUF chat templates to inject instructions when a trigger appeared, without changing any weights (AML.CS0064). ATLAS's description of unsafe AI artifacts (AML.T0011.000) makes the general point: an artifact can alter model behavior through features the runtime supports on purpose, with no software bug at all. A safe format removes code execution at load time; it does not make the content trustworthy, which is why [[model-provenance]] still matters.

```python
import hashlib
import pickle
from safetensors import safe_open

# Vulnerable: unpickling runs whatever the file's author chose.
with open("downloads/helper-7b.pkl", "rb") as f:
    model = pickle.load(f)

# Fixed: check the reviewed digest, then read tensors from a data-only format.
EXPECTED_SHA256 = "..."  # recorded when the file was reviewed (see AI-05)
path = "models/helper-7b/model.safetensors"
with open(path, "rb") as f:
    digest = hashlib.file_digest(f, "sha256").hexdigest()  # Python 3.11+
if digest != EXPECTED_SHA256:
    raise RuntimeError("model file does not match the reviewed artifact")
with safe_open(path, framework="pt", device="cpu") as f:
    tensors = {name: f.get_tensor(name) for name in f.keys()}
```

### Network exposure: who can reach the server?

A server listens on an [[ip-address]] and a [[port]]. The loopback address (127.0.0.1 in IPv4, ::1 in IPv6) accepts connections only from the same machine. The address 0.0.0.0 (or `::`) means every interface, so anyone who can route to the machine can connect unless a [[firewall]] stops them. Containers add a trap: publishing a port as `-p 8080:8080` typically listens on all of the host's interfaces, while `-p 127.0.0.1:8080:8080` keeps it local. Reverse proxies and tunnels can expose a loopback service too, and in the AML.CS0048 case a proxy misconfiguration let the researcher bypass authentication.

```bash
# Exposed: every interface, no key (llm-serve is a fictional server).
llm-serve --model models/helper-7b/model.safetensors --host 0.0.0.0 --port 8080

# Local only, with a key file that only this account can read.
llm-serve --model models/helper-7b/model.safetensors --host 127.0.0.1 --port 8080 \
  --api-key-file ~/.config/llm-serve/api-key

# Containers: publish on loopback only, and pin the image by digest.
docker run -p 127.0.0.1:8080:8080 example/llm-serve@sha256:<reviewed-digest>
```

Loopback is not a complete boundary. It keeps other machines out, but not other accounts or malware on the same machine, and browsers face [[dns-rebinding]], in which a web page's name is rebound to an address on the visitor's own machine or network. Require a key even on loopback.

### Authentication, quotas, and logs

ATLAS recommends requiring "authentication for API endpoints" and monitoring production model queries (AML.M0019). Issue one key per user rather than a shared key, so you can set quotas, revoke one person, and attribute requests. Keep keys and connected-service credentials in a [[secrets-management]] system or the operating system's keychain, not in configuration files, which is where the AML.CS0048 credentials sat.

Quotas protect availability and cost, a risk OWASP's 2026 list calls unbounded consumption (LLM06:2026). ATLAS advises bounding "input size, batch size, execution time, memory, compute, and output size," limiting context and output tokens, and, for agents, capping iterations, retries, and tool calls (AML.M0036), alongside per-identity rate limits (AML.M0004).

Logs need the same care as the data in them: prompts may contain personal information, so record metadata by default and apply the minimization and retention rules from [the privacy lesson](lesson:AI-07).

### Sandboxing tool use

When a local model can run code, assume an injected instruction will eventually reach it, and limit what the code can touch. ATLAS's guidance on segmenting agent components says to "isolate code execution via containers or virtual machines, restrict filesystem and network access, and limit tool invocation rates," and to build each run from a clean base image without carrying state forward (AML.M0032). A [[sandbox]] built on a [[container]] shares the host kernel; use a virtual machine when the risk justifies it.

```bash
# One tool call: fresh container, no network, read-only inputs, no root, bounded resources.
docker run --rm --network none --read-only --user 1000:1000 --cap-drop ALL \
  --memory 512m --pids-limit 128 -v "$PWD/course-files:/data:ro" \
  python-sandbox@sha256:<reviewed-digest> python /data/task.py
```

### Updates, licenses, and copies

Separate two kinds of update. Runtime and library patches close known vulnerabilities; apply them promptly. In the ShadowRay case, Ray's maintainers fixed four of the five reported vulnerabilities, while the fifth, CVE-2023-48022, remains disputed because they consider the missing authentication a design decision for trusted networks. New model files, templates, and tools are new artifacts: review, pin, and test them before switching, because ATLAS describes "rug pulls," in which a component gains users and then ships a malicious update (AML.T0109). An AI bill of materials, listing every artifact you run, makes both kinds trackable (AML.M0023).

Licenses travel with the weights; record each model's terms in your inventory, as described in [the provenance lesson](lesson:AI-05). NIST AI 600-1 lists intellectual property among its twelve generative AI risks. Finally, weights that ship to users' devices can be copied: ATLAS records researchers who recovered models from a mobile photo app, including encrypted ones, after the app decrypted them at runtime (AML.CS0058), and it notes that edge deployment increases the attack surface (AML.M0017).

## Worked example

**Reviewing inference access, quotas, updates, and isolation.** The course `cs101.example` runs a shared model server for 40 students on a lab machine at 198.51.100.20. Alice, the instructor, reviews it with Bob, a TA.

| Area | Finding | Fix |
| --- | --- | --- |
| Access | Listens on 0.0.0.0:8080 with no key; reachable from the whole campus network | Bind to 127.0.0.1; students connect through the course's authenticated proxy with per-student keys |
| Quotas | No limits; one very long request stalled the GPU for everyone | Per-key rate, concurrency, token, and time limits |
| Model files | `helper-7b.bin`, pickle-based, from an unknown uploader | Replace with the reviewed safetensors file and pin its digest |
| Updates | Runtime unpatched for over a year; model re-downloaded by name at each restart | Patch on advisories; pin model files; review model updates |
| Isolation | Python tool runs inside the server process as root | Disposable container, no network, read-only course files, non-root user |
| Logs | Full prompts kept indefinitely | Metadata only, 30-day retention, restricted access |
| License | Model allows non-commercial use | Acceptable for teaching; recorded in the inventory |

The revised configuration records each decision:

```yaml
# llm-serve configuration after review (fictional server)
listen: 127.0.0.1:8080              # reached only through the course's authenticated proxy
auth:
  require_api_key: true
  keys_file: /etc/llm-serve/keys    # one key per student; readable only by the service
model:
  path: /srv/models/helper-7b/model.safetensors
  sha256: "<recorded at review>"
  auto_update: false                # model updates go through review first
limits:
  max_input_tokens: 8000
  max_output_tokens: 1024
  requests_per_minute_per_key: 20
  max_concurrent_per_key: 2
  request_timeout_seconds: 60
tools:
  python:
    sandbox: container              # fresh per call, no network, read-only inputs, non-root
logging:
  store_prompts: false              # metadata only
  retention_days: 30
```

**Verify, don't assume.** From another machine, a connection to port 8080 must fail. Through the proxy, a request without a key must be rejected, and an oversized request must hit the limit. On the server, `ss -ltn` must show the service on 127.0.0.1 only. Inside the sandbox, a network request must fail.

**Residual risks.** The proxy is now the exposure point, and AML.CS0048 shows how a proxy misconfiguration can undo authentication, so Alice tests it after every change. Containers share the host kernel. Students with valid keys can still try prompt injection, but its reach is now limited to the sandbox. The model's training remains unverifiable, as the provenance lesson explains.

## Defenses

- **Load only data-only formats** such as safetensors, and verify digests before loading (AML.M0014). _Limit:_ templates and configuration can still shape behavior.
- **Bind to loopback and require per-user authentication.** _Limit:_ proxies, tunnels, and port mappings can re-expose the service, so test from outside.
- **Set quotas and resource limits** on tokens, time, memory, concurrency, and tool calls. _Limit:_ limits that are too tight break legitimate work, so tune them with real usage data.
- **Sandbox tools** in disposable containers or virtual machines with no network, no root, and minimal files, following [[least-privilege]]. _Limit:_ sandbox escapes exist, and data inside the sandbox can still be misused.
- **Keep secrets out of configuration files and prompts.** _Limit:_ the service still needs some credential, so scope it narrowly.
- **Patch runtimes promptly; review model and tool updates.** _Limit:_ disputed or unpublished flaws, like ShadowRay's, may not appear in vulnerability scans.
- **Inventory models, licenses, and digests.** _Limit:_ an inventory is only as current as its update process.

## Common misconceptions

- **"It runs on my laptop, so it's private."** A server listening on all interfaces is reachable from the whole network.
- **"A model file is just numbers."** Pickle-based files can run code, and templates can carry instructions.
- **"The hub scanned it, so it's safe."** Scanners missed the deliberately corrupted pickles in AML.CS0031.
- **"Localhost means nobody else can reach it."** Other software on the same machine can, and proxies or tunnels can expose it.
- **"Auto-updating to the latest model keeps us secure."** Runtime patches should be fast; model updates need review.
- **"Open weights means any use is allowed."** Licenses vary and can restrict use.

## Key takeaways

- A local model is a stack of model files, an inference server, tools, and a host, and each layer needs its own controls.
- Pickle-based model files can run code when loaded; prefer safetensors, verify digests, and remember that templates and configuration still shape behavior.
- Bind inference servers to loopback, require per-user keys even there, and test exposure from another machine.
- Bound every request and agent loop with quotas, and run tool calls in disposable, network-less, unprivileged sandboxes.
- Patch runtimes quickly but review model and tool updates like new artifacts, and record licenses alongside digests.
